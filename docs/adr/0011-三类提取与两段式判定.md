# 0011 提取改为三类目标，并用视觉判定兜住「没有就不提取」

- 状态：已采纳（2026-11-21）
- 修订：ADR 0010 第 2 条（类别定义）、ADR 0009（提取目标描述）

## 背景

ADR 0010 把提取类别定为「材质纹理 / 边框样式」，是按「取一块表面」设计的。
真实需求是**从一张桌面照片里取出三种可独立使用的素材**：

1. 桌面/桌垫的**俯视图**（去掉摆件、补全遮挡、保持比例、无透视）；
2. 桌垫上**可四方连续的基本纹理**单元；
3. 印刷在桌垫上的**形象设计**（卡通人物、插画、物品）。

并且明确要求：**有就提取，没有就不提取，允许失败。**

## 决策

### 1. 类别替换为三类

| key | 中文 | 提取目标描述（进提示词） |
| --- | --- | --- |
| `topdown` | 桌面俯视图 | 从正上方看桌面/桌垫的完整画面；去掉桌面上的摆件与杂物，被遮挡处按周围材质补全；保持原画面长宽比；不要透视畸变 |
| `texture` | 基本纹理 | 只取桌垫上重复出现的那一块纹理单元；画面内纹理均匀、边缘可平铺；不要出现桌垫边缘与场景 |
| `graphic` | 形象设计 | 只取印刷在桌垫上的图案（卡通人物、插画、物品）；正面俯视、无角度、背景干净 |

旧的 `material` / `border` 删除；`other` 只保留给历史数据。

### 2. 两段式：先判定，再提取

**图生图模型只会给图，不会说「没有」**。直接提取不存在的目标会**幻觉出一张不存在的图案**，
这比提取失败更糟——用户会把它当成真实素材。

因此每条（原图 × 类别）先调一次视觉模型（`magpie-vision` 的 `analyze_image`）问
「这张图里是否存在该目标」，只有「存在」才发起图生图；「不存在」记 `skipped`，不消耗生图调用。

### 3. 新增明细表与「无内容」终态

`extraction_item`：一条 = 一次（原图 × 类别）的尝试，记录 `status`（succeeded / skipped / failed）、
`library_asset_id`（成功时）与失败原因。

`extraction_run.status` 增加 `empty`：全部条目都 `skipped` 时记这个终态，
界面显示「未发现可提取内容」，**不算失败**，也不产出素材。

### 4. 输出比例跟随原图

不再固定 1024×1536。`size` 由原图长宽比推导（长边 1536，短边按比例取整），
保证俯视图不变形。代价是同一批产物尺寸不统一，界面按实际尺寸展示。

### 5. 四方连续只做提示，不保证

提示词要求「边缘可平铺」，但**模型直出很难真正无缝**。本版本不做偏移+接缝修补，
验收时人工检查并在报告里如实标注接缝情况。真正无缝需要确定性图像处理，另开节点。

## 后果

- 收益：三类产物各自可用；幻觉风险被视觉判定挡住；俯视图不变形。
- 代价：每张原图 × 每类多一次视觉调用（便宜）；`extraction_item` 多一张表；
  产物尺寸不统一，界面不能假设固定比例。
- 风险：视觉判定本身可能误判（漏判 → 少提取；误判 → 仍可能幻觉）。误判要能在界面看出来，
  所以每条 `skipped` 都要显示「判定为不存在」的依据（模型原话）。

## 备选与放弃原因

- 不做判定直接提取：会产生幻觉素材，最坏情况。
- 固定 1024×1536：俯视图会被拉伸变形。
- 生成后做接缝修补：需要新的图像处理模块，超出本次范围。
