# 13 四角框选与单应透视矫正

> 依赖：01 资源夹、05 提取、12 素材库
> 相关：[ADR 0013](../adr/0013-几何矫正与模型提取分开.md)

## 目标

给原图加一个**四角框选**编辑器：用户在照片上把桌面/桌垫（或印在上面的图案）的四个角对齐，
系统用**单应变换**把这块四边形矫正成正视矩形，并用消失点法算出它的**真实长宽比**，
作为提取的输出尺寸与正面视图的输入。

几何必须由代码算，不能交给生成模型。

## 为什么必须这么做（实测依据）

| 事实 | 后果 |
| --- | --- |
| `deriveExtractionSize` 按**原照片**长宽比推算输出尺寸 | 照片是斜拍的，桌面在画面里是梯形，比例本就不是桌面的真实比例 |
| 提示词要求模型「拉平成正面视角」 | 模型只会「看起来像」，不会真的做透视矫正，且常把梯形压成矩形导致内容被拉伸 |
| 图生图实测 4 次运行只有 1 次文字全对，角色每次都被重画 | 即使提示词明写「不要摆正透视」，模型仍然自行重画。**只要矫正由模型做，文字与角色就永远不可靠** |

## 概念

| 概念 | 含义 |
| --- | --- |
| 框选（quad） | 原图上的四个归一化坐标点，顺序为「左上、右上、右下、左下」 |
| 框选用途（quad kind） | `surface`（桌面/桌垫四角）或 `pattern`（图案本身的四角） |
| 矫正图（rectified） | 单应变换后的正视矩形，按估算比例输出，固定 PNG |
| 几何矫正产物 | `graphic` 类别在已框选 `pattern` 时**直接**取矫正图，全程不调用模型 |
| 模型提取产物 | 其余情况由生成模型产出，模型会重画 |

## 数据模型

`media_asset` 新增五列，全部可空、不回填（老照片行为不变）：

```
media_asset
  quad             jsonb     -- [[x,y]×4]，归一化 0–1；未框选为 NULL
  quad_kind        text      -- surface | pattern
  quad_real_width  int       -- 用户手输的实际宽度（毫米），可空
  quad_real_height int       -- 用户手输的实际高度（毫米），可空
  rectified_key    text      -- 矫正图的 storage_key；矫正失败为 NULL，四角仍保留
```

`library_asset` 新增一列：

```
library_asset
  source  text  NOT NULL DEFAULT 'model'  -- model | rectified
```

`source` 记录产物的真实来源。老素材全是模型产物，默认值就是它们的真实来源。

## 设计契约

### MUST

1. **`graphic` 类别在已框选 `pattern` 时不经模型**：产物 = 单应矫正后的裁切图，全程不调用生成模型
   （不判定、不要材质描述、不生图）。产物是原图像素的几何变换结果，所以文字与角色**必然原样**。
2. **界面上必须能区分来源**：「几何矫正（原样）」与「模型提取（可能重画）」两种来源都要看得见，
   不能让用户以为模型产物是原样。
3. **长宽比由消失点法推算**：两条对边的交点给出两个消失点，由消失点与主点解出焦距，
   从而得到真实长宽比。假设针孔相机、方形像素、主点在画面中心。
4. **手输实际尺寸优先于估算**：两者冲突以手输为准。
5. **估算失败不阻断**：点退化、只有一组对边平行、比例超出 `[0.2, 5]` 时退回原图比例，
   界面显示「比例未能估算」，提取仍可进行。
6. **只接受凸四边形**：凹四边形与自交四边形不得保存，界面禁用保存并给出可读提示。
7. **输出尺寸沿用提取的硬约束**：32 的倍数、∈ `[512, 1536]`、比例 ≤ 3:1，但按**估算比例**
   而不是原照片比例推导。
8. **不改原图**：只新增矫正图与四点；清除框选时四列一起清空，矫正图一并删除。
9. **确定性**：同一张原图、同一组四角，重复矫正得到**字节级完全一致**的产物。

### SHOULD

- 两种框选用途（桌面四角 / 图案四角）要在保存时选出来：`graphic` 只认图案框选，
  `topdown` / `texture` 只认桌面框选。用途与类别不匹配时退回原图，不硬套。
- 原图长边 < 1000px 时提示「分辨率偏低，矫正后可能模糊」，但**不阻止**保存。
- 框选编辑器的手柄要能键盘微调（方向键细调、Shift 加速）。

### MAY

- `topdown` / `texture` 仍走模型，输入换成矫正后的图。

### MUST NOT

- **不得**只做「矫正图当模型输入」就宣称问题解决 —— 那还是重画。
- 不得自动检测四角（先手动，可靠优先）。
- 不得支持一次矫正多个平面。
- 不得为了矫正在客户端解密或直连上游模型。

## 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| PUT | `/api/library/assets/[id]/quad` | 保存四角：`{ kind, points, realSize? }`，同步生成矫正图 |
| DELETE | `/api/library/assets/[id]/quad` | 清除框选与矫正图 |
| GET | `/api/files/assets/[assetId]/rectified` | 鉴权读取矫正图，`?w=400` 当场缩放 |

`PUT` 的响应带上这次判定的长宽比与来源：

```
{ assetId, quad, quadKind, realSize,
  aspectRatio, aspectSource: "manual" | "estimated" | "fallback",
  estimatedAspectRatio,
  rectifiedUrl, rectifiedWidth, rectifiedHeight, rectifiedError }
```

矫正失败时 `rectifiedUrl` 为 `null`、`rectifiedError` 给出可读原因，四角照常保存。

## 验收标准

| 编号 | 断言 |
| --- | --- |
| AC-QUAD-1 | 拖四个角后保存：`media_asset.quad` 存下 4 个归一化点，`rectified_key` 有值，磁盘能读到矫正图 |
| AC-QUAD-2 | 对一张合成图（已知矩形按透视投影得到）做矫正：估算长宽比误差 ≤ 10%，矫正图的长宽与原矩形同向 |
| AC-QUAD-3 | 提取用矫正图作输入：产出尺寸满足 32 倍数 / ∈[512,4096] / ≤3:1，且比例等于估算值（非原照片比例） |
| AC-QUAD-4 | 凹四边形或自交四边形：保存按钮禁用，给出可读提示 |
| AC-QUAD-5 | 估算失败时退回原图比例，界面显示「比例未能估算」，提取仍可进行（不阻断） |
| AC-QUAD-6 | 手工输入实际尺寸时以其为准（与估算值冲突时用输入值） |
| AC-QUAD-7 | 未校正的原图：行为与现在一致，结果卡上有「未校正」标注 |
| AC-QUAD-8 | `pnpm check`、`test:integration`、`test:e2e` 全过；单应与比例估算必须有纯函数单测（含退化输入） |
| AC-QUAD-9 | 框选图案四角后，`graphic` 产物里的文字与原图逐字一致（像素级，非模型生成），来源标记为「几何矫正」 |
| AC-QUAD-10 | 同一张图连续跑两次 `graphic`（几何矫正路径），产物字节级完全一致（证明没有模型参与） |
| AC-QUAD-11 | 未框选时 `graphic` 走模型路径，产物必须标注「模型提取（可能重画）」 |

## 验证方式

```bash
pnpm check && pnpm test:integration && pnpm test:e2e
```

比例准确性用**合成图**验证（已知真实尺寸 + 已知视角投影），不靠肉眼：
单测在 `src/modules/media-collection/quad.test.ts`，端到端在
`tests/integration/quad-rectify.test.ts`（把已知图案按已知投影拍成照片，再让矫正复原它，
比较逐像素差异）。

## 已知限制

- 单张矩形只在一个方向有透视时（一组对边保持平行，例如只俯仰不偏摆的俯拍）**给不出焦距约束**，
  比例在数学上不可复原。此时按契约退回原图比例并提示「比例未能估算」——
  这是几何上的固有限制，不是实现缺陷。手输实际尺寸可以绕过它。
- 重采样用双线性，倍率很大时会略糊；不上采样（不放大）以免把低分辨率原图拉糊。
- 只支持一个平面：同时框选桌面与立起来的部分不在本版范围。
