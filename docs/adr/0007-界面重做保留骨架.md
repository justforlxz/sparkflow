# 0007 界面按 Apple HIG 重做，保留现有骨架

- 状态：已采纳（2026-11-19）
- 相关：09 工作台、全部页面、`docs/design/`

## 背景

第一版交付后实测：`globals.css` 里定义了设计变量（`--bg #f6f7f9`、`--panel`、`--accent #ef4d63`、
`--radius 14px`…），但 **28 个页面/组件文件全部用 Tailwind 默认灰阶（`zinc-`/`gray-`/`slate-`），
0 个文件引用那套变量**。也就是设计系统只写在样式表里，没有被后续节点执行。

结果是界面能用，但与已确认的 V5 原型在密度、层级、强调色、圆角与交互反馈上差别明显。

## 决策

以现有 V5 原型为**骨架**（侧栏 + 内容区、页签结构、信息层级、页面路由都不动），
用 Apple HIG 的工艺标准重做**视觉与交互**：

1. 颜色只允许来自 `globals.css` 的设计变量；禁止 `zinc-`/`gray-`/`slate-` 等默认色阶。
2. 字号与行高按固定阶梯（11/12/13/15/17/22/28），不随手写 `text-sm`。
3. 圆角、阴影、间距各一套刻度；卡片半径 14，面板阴影只保留一档。
4. 状态色语义固定（待创作/生成中/待发布/已发布），不再每页重定义。
5. 交互态补齐：hover / focus-visible / disabled / loading / empty / error，
   键盘可达，焦点环可见。
6. 动效克制：只保留 150–200ms 的属性过渡，不做装饰性动画。

## 为什么保留骨架

- 布局与信息架构已经过验收（AC-09-*），推翻等于把验收过的结构重来一遍。
- 问题在「执行」，不在「设计」。重做视觉与交互品质能直接解决偏差，成本比重构低一个量级。

## 后果

- 收益：设计系统终于有唯一来源；后续新页面照刻度写，不再各自发明。
- 代价：需要一次全站扫描（约 28 个文件），并且要用 `apple-design` skill 的 HIG 清单核对
  对比度、点击区域、空态文案、表单错误提示等工艺项。
- 约束：`docs/acceptance.md` 增一条「页面源码中不得出现默认色阶」的检查，防止回退。
