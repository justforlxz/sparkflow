# 0002 生成任务用单进程内 worker 执行

- 状态：已采纳（2026-11-17）
- 相关：04 创作任务、部署形态

## 背景

生图要几十秒到几分钟，不能占着 HTTP 请求。可选方案：请求内同步执行、独立 worker 容器、
引入 Redis 队列、进程内后台循环。

## 决策

在同一个 Next.js 进程里跑一个后台循环：轮询数据库里 `status = queued` 的任务，
一次执行一个，按阶段推进；服务启动时把残留的 `running` 标记为失败（原因为服务重启）。

## 后果

- 收益：一个容器、一份日志、一次部署；不需要新的外部依赖；重启恢复语义清晰。
- 代价：任务执行与 web 进程同生命周期，进程被杀就中断（已由「启动时清理遗留状态」兜住）；
  多实例部署会重复执行，因此**本项目明确不做多实例**。
- 迁移路径：将来要并发或多实例，只需把「取任务」换成带锁的选择语句（`FOR UPDATE SKIP LOCKED`），
  阶段逻辑不变。

## 备选与放弃原因

- 独立 worker 容器：多一个容器与服务，收益只在多实例时出现。
- Redis + 队列：为单用户项目引入第二套存储与运维面，不划算。
