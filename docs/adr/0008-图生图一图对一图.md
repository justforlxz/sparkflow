# 0008 图生图启用，并改成「一图对一图」

- 状态：已采纳（2026-11-19）
- 取代：ADR 0003 里「图生图本版本不实现」的部分、ADR 0004 的早期方案

## 背景

第一版把图生图关掉了（功能开关 `image-to-image` 为「本版本未实现」），生图是「固定 N 张、
不读原图」。实测下来这不是用户要的东西：他要的是**每张素材图各出一张成品图**，
并且文案要写得出照片内容。

同时上游条件变了：不再用 magpie 内置的图片 MCP，改用 `magpie-image-edit` 插件，
它的 `edit_image` 工具直接支持「拿一张或几张图去改」。

## 决策

1. 打开功能开关 `image-to-image`（注册表 `implemented: true`）。
2. 生图语义改为**一图对一图**：资源夹 N 张原图 → N 次 `edit_image` → N 张成品图，
   顺序与原图一致；`generated_asset` 增加 `source_asset_id` 记录对应关系。
3. **取消任务的「图片数量」参数**：张数由原图数量决定，任务页只显示「将生成 N 张」。
4. **一次任务内跑完全部原图**，不拆成多个任务、不分批；单张失败不丢弃其它张（阶段判 `partial`）。
5. 文案阶段先做**视觉提取**（每张原图一条中文描述），再汇总成一条文案（见 PRD 06）。

## 后果

- 收益：产物与素材一一对应，用户能逐张对照；文案有照片内容作依据。
- 代价：一次任务的上游调用次数 = 原图数量（此前固定几次），耗时与成本随素材量线性增长；
  任务超时上限从 15 分钟放宽到 45 分钟。
- 取消项：`generation_task.image_count` 字段与创建任务时的张数选择一并废弃（保留历史数据）。

## 备选与放弃原因

- 保留「固定 N 张」：无法满足「每张素材都要有一张成品」的核心诉求。
- 把原图分组映射到 N 张：语义模糊，用户无法预期哪张原图对应哪张成品。
