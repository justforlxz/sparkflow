# 09 工作台、导航与全局状态

> 依赖：01、02、03、07、08 ｜ 收尾功能

## 目标

给用户一个入口页，一眼看清内容生产状态；同时把导航、布局、空态、加载态、错误提示统一起来。

## 范围

包含：工作台（统计与最近列表）、应用外壳（侧栏导航 + 顶栏）、统一的状态组件与交互反馈。

不包含：图表化分析、按时间维度的趋势统计。

## 设计契约

### 应用外壳

MUST：

1. 布局与 V5 原型一致：左侧固定侧栏（品牌、导航、当前用户区）、右侧内容区。
   导航项：工作台、媒体资源夹、创作任务、发布记录、模型与 Agent 设置。
2. 侧栏「媒体资源夹」「创作任务」显示真实计数，由 `/api/stats` 提供，不用硬编码。
3. 窄屏（< 720px）侧栏折叠为图标模式，导航仍可用。
4. 统一组件：`Panel`（卡片）、`EmptyState`、`LoadingState`、`ErrorState`、`Toast`、`ConfirmDialog`、
   `Pill`（状态标签）。所有页面复用，不允许各页面自己写一套。

### 工作台

MUST：

1. 统计四项：媒体资源夹总数、待创作（无结果）、待发布（有结果未发布）、已发布。数值来自单次聚合查询。
2. 「最近的媒体资源夹」（最多 6 条）与「最近生成的内容」（最多 4 条），点击可进入详情。
3. 「新建媒体资源夹」入口与「查看全部」跳转。
4. **不显示任何演示数字或占位图片**；没有数据时显示空状态与引导。

SHOULD：

- 统计接口只做一次往返（`/api/stats` 返回全部四个数字 + 两个最近列表）。
- 状态标签颜色语义固定：待创作=蓝、生成中=强调色、待发布=橙、已发布=绿。
- 全局错误提示统一走 toast，错误信息使用后端返回的 `error.message`，不拼接技术细节。

MAY：

- 顶栏显示当天日期与「今天已完成 N 次创作」之类的轻量信息（数据必须真实）。

MUST NOT：

- 不得把统计写成前端遍历全量列表计算（数据量上来会拖慢首页）。
- 不得在页面里写死颜色值（必须用 `globals.css` 的设计变量）。

## 数据与接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/stats` | `{ collections, pendingGeneration, pendingPublish, published, recentCollections, recentResults }` |

## 验收标准

| 编号 | 断言 | 自动化用例 |
| --- | --- | --- |
| AC-09-1 | 初始状态下四个统计都是 0，页面显示空状态而不是假数据 | `tests/e2e/dashboard.spec.ts` |
| AC-09-2 | 新建资源夹后，「媒体资源夹总数」与「待创作」各加 1 | 同上 |
| AC-09-3 | 产生结果后，「待创作」减 1、「待发布」加 1 | 同上 |
| AC-09-4 | 标记发布后，「待发布」减 1、「已发布」加 1，最近内容里出现该条目 | 同上 |
| AC-09-5 | 侧栏计数与工作台统计一致 | 同上 |
| AC-09-6 | 点击「查看全部」「最近的资源夹」跳转正确 | 同上 |
| AC-09-7 | 窄屏（375×812）下侧栏折叠，五个导航项仍可点击进入对应页面 | 同上（viewport 覆盖） |
