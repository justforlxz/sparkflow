# 08 发布准备、导出与发布记录

> 依赖：07 结果管理 ｜ 含「分享留空」的明确边界

## 目标

把一组创作结果整理成可以直接手动发布到小红书的图文：选图、检查文案、下载图片、复制文案，
发布完成后回到系统标记为已发布并留下记录。

## 范围

包含：发布准备弹窗、选图、文案编辑、批量下载（ZIP）、复制到剪贴板、标记已发布、发布记录（全局 + 资源夹内）。

不包含（明确不做）：

- **不接入小红书分享**。界面保留「分享到小红书」按钮，点击后**只在站内提示「分享功能不可用」**，
  不打开新窗口、不调用任何外部接口、不写入任何发布状态。
- 不做账号授权、不做发布接口对接、不做发布结果回执。

## 设计契约

### 发布准备

MUST：

1. 弹窗展示当前结果的全部图片，默认全选，可单张取消勾选。
2. 标题、正文、话题标签可在此处编辑；保存时写回 `generation_result`。
3. 「下载所选图片」：选 1 张时直接下载该文件；选多张时打包 ZIP（文件名含序号，保证可排序）。
4. 「复制文案」：按「标题 + 空行 + 正文 + 空行 + `#标签` 空格分隔」的固定格式写入剪贴板，
   格式必须与小红书粘贴后的观感一致。复制失败要给出提示（浏览器权限被拒时）。
5. 「标记为已发布」：创建或更新 `publish_record`，记录平台（默认小红书）、发布日期、
   标题快照、所选图片 id 列表。
6. 同一结果重复标记时**更新**已有记录，不重复创建（`result_id` 唯一约束）。
7. 标记发布只是记录用户反馈，界面上不能出现「已同步到小红书」这类误导文案。

### 分享按钮（明确留空）

MUST：

1. 按钮存在，文案为「分享到小红书」。
2. 点击后在站内以 toast / 提示条形式显示「分享功能不可用」，**不显示成功语义**、不改变任何状态。
3. 不发起任何网络请求（可用 e2e 断言「点击后没有新增 /api 请求」与「没有 window.open」）。

### 发布记录

MUST：

- 全局 `/published` 页与资源夹详情「发布记录」页签展示同一份数据。
- 记录项展示：结果缩略图、标题、发布时间、图片数量、来源资源夹。
- 删除结果时，其发布记录一并删除。

SHOULD：

- 发布记录按发布时间倒序，支持按资源夹筛选。
- 记录里保留 `title_snapshot`，即使之后编辑结果也能看出当时发布用的标题。

MUST NOT：

- 不得在用户未点击「标记为已发布」时把任何结果显示成已发布。
- 不得由系统自动推断发布成功。

## 数据与接口

`publish_record`：id、result_id（unique）、platform、published_at、title_snapshot、selected_asset_ids（uuid[]）、created_at、updated_at

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/results/[id]/publish` | 标记已发布（幂等：已有则更新） |
| DELETE | `/api/results/[id]/publish` | 撤销发布记录 |
| GET | `/api/publish-records` | 全局列表（分页、可选按资源夹筛选） |
| GET | `/api/collections/[id]/publish-records` | 资源夹内列表 |
| GET | `/api/results/[id]/download?assets=a,b` | 单张直接返回字节，多张返回 ZIP |
